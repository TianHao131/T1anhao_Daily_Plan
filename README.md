# 每日任务：GitHub Pages + Supabase

每日任务作为独立网站发布，使用自己的 GitHub 仓库和网址。导航网和每日任务共用同一个 Supabase 项目、同一个同步账号，但分别保存到两张表。

独立仓库：https://github.com/TianHao131/T1anhao_Daily_Plan

开启 GitHub Pages 并发布后，网站地址为：https://tianhao131.github.io/T1anhao_Daily_Plan/

## 上线顺序

1. 在现有 Supabase 项目的 SQL Editor 中运行本目录 `setup.sql` 的实际内容。不是复制文件路径。最后应显示 `row_security=true`、`force_row_security=true`、`policies=3`。脚本只创建每日任务自己的表，不改导航网表。
2. 将本目录里面的全部文件上传至上面的每日任务仓库根目录，使 `index.html` 直接位于根目录。不要上传到导航网仓库，也不要在新仓库中再套一层 `daily-checkin` 文件夹。ZIP 需要先解压，再打开文件夹选择里面的文件上传；不要把 ZIP 本身上传。在新仓库 Settings → Pages 中选择 main 分支、根目录发布。
3. 等 Pages 发布完成，打开新网址。使用导航网已有的同步邮箱和密码登录，不需要重新注册。每日任务单独记住登录状态，因此每个浏览器首次打开每日任务时登录一次，后续自动恢复。
4. 在旧的本地每日任务网页中打开“数据管理”，导出 JSON。在新网站中使用“导入恢复”，选择该 JSON。导入会替换当前账号的任务并自动同步。不要将私人备份上传 GitHub。
5. 等到“已与云端同步”，再用另一台设备登录核对。没有这一步之前，请保留旧网页和备份。

## 使用方式

- 修改先存到当前账号的本机缓存，500 毫秒后尝试上传；当前页面可断网继续修改。
- 页面打开、回到前台、网络恢复以及可见时每 20 秒尝试同步。可手动点击“同步”。
- 缓存采用按账号隔离的键 `daily-checkin-cloud-v1:<userId>`。与原本地网页的 `daily-checkin-data` 不混用。
- Supabase 使用持久登录和自动续期；清除浏览器数据、主动退出、登录失效后需要重新登录。首次打开的新设备需要联网。
- 已有登录和有效缓存时，网络暂时不可用可尝试打开缓存；若登录组件无法恢复会话，需要联网后重试。此版本没有离线安装/PWA，不承诺全新离线打开。
- 同一浏览器支持 Web Locks 时，只允许一个每日任务标签页编辑，避免两个标签页覆盖同一份未上传的缓存；不同电脑/浏览器仍可并行修改。
- 修改顺序、完成记录、任务字段分开合并。相同任务字段、删除与编辑、相冲突的顺序会弹窗要求选择；其他互不冲突的修改会保留。
- 冲突草稿会保存在本机，重新打开后仍可处理。冲突弹窗可先导出备份。
- 清空和导入也会同步到云端；均保留当前会话的一次撤销。

## 权限与数据

- 使用导航网现有的 Supabase 项目和账号。每日任务的数据在单独的 `daily_checkin_state` 表中。
- RLS 强制开启。匿名账号没有表权限，已登录账号只能读写自己的行。
- 前端只能写入 `data`。版本号由数据库触发器递增，更新时必须匹配读取的版本，防止旧内容直接覆盖新内容。
- `cloud-config.js` 只有供浏览器使用的 Publishable key，不能放入 Secret key、service_role 或数据库密码。
- 发布目录只有空页面和程序，不含旧任务、浏览器记录或账号密码。
- 每日任务使用自己的登录存储键 `daily-checkin-auth-v1`，导航网继续使用原来的登录存储。账号相同，日常登录状态各自记住；在 Supabase 中全局撤销会话、删除账号或暂停共享项目，仍可能同时影响两个网站。
- 免费 Supabase 项目可能因一周低活跃而暂停；需从 Supabase 后台恢复。内地访问仍受网络连接情况影响。

## 保留的功能与兼容修复

每日习惯、归档与历史记录、每月任务、作业布置、复制任务、日期双色与双色描边、任务顺序、计划待办、统计、导入导出继续保留。源文件中仍有复制逻辑但缺少按钮，本版本恢复了复制入口。

旧 JSON 导入会继续兼容原网页的日期完成记录和标签迁移。

测试脚本和原始文件备份保留在本地 `work/daily-sync` 中，未包含在公开发布目录。

## 管理范围

- 修改、重新发布或删除每日任务的 GitHub 仓库，均独立于导航网仓库。
- 收藏位于 `navigation_bookmark_state`，每日任务位于 `daily_checkin_state`；相同账号的用户 ID 分别关联各自的数据行。
- 这是便于管理的两个独立网站，共享 Supabase 的账号体系和项目资源。Supabase 项目的额度、服务状态和账号管理不是完全分开的。
